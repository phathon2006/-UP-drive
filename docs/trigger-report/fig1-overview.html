รายงาน Database Trigger

ระบบแชร์รถมหาวิทยาลัยพะเยา — UP Drive

รายงานแสดง Trigger ของกลุ่ม (Database Trigger / PostgreSQL) พร้อมผลการทดสอบจริง

1. Trigger คืออะไร

Trigger (ทริกเกอร์) คือชุดคำสั่งที่ฐานข้อมูลเรียกให้ทำงาน อัตโนมัติ เมื่อเกิดเหตุการณ์ (event) กับตาราง เช่น มีการ INSERT, UPDATE หรือ DELETE โดยไม่ต้องให้โปรแกรมฝั่งแอปสั่งเอง ทำให้กติกาของระบบถูกบังคับใช้ที่ฐานข้อมูลเสมอ แม้มีโปรแกรมหรือคน เข้าถึงข้อมูลหลายทาง

ใน PostgreSQL/ Supabase ประกอบด้วย 2 ส่วน:

  • Trigger Function — ฟังก์ชันภาษา PL/pgSQL ที่ทำงานจริงและ RETURN NEW
  • CREATE TRIGGER — ผูกฟังก์ชันกับตาราง ระบุว่าให้ทำงาน ก่อน (BEFORE) หรือ หลัง (AFTER) การแก้ไข

2. ทำไมกลุ่มเราจึงเลือกใช้ Trigger

ระบบ UP Drive เดิมตั้งค่าเวลาและตรวจสอบกติกาจาก โค้ดฝั่งเซิร์ฟเวอร์ (Node.js) ซึ่งมีข้อเสียคือ ถ้ามีการแก้ข้อมูลจากช่องทางอื่น (เช่น SQL Editor หรือ API ตรง) กติกาจะถูกข้ามได้ กลุ่มเราจึงย้ายกติกาสำคัญ 3 ข้อไปเป็น Trigger เพื่อให้ฐานข้อมูลคุมเอง:

  • ตั้งเวลาอัตโนมัติ — เมื่อกลุ่มเปลี่ยนสถานะ ให้บันทึกเวลา confirmed_at / accepted_at / completed_at ให้เอง
  • บังคับกติกาความถูกต้อง — ห้ามตั้งสถานะ accepted ถ้ายังไม่มีคนขับ
  • อัปเดตตำแหน่งล่าสุด — เมื่อพิกัดคนขับถูกแก้ ให้ updated_at เป็นเวลาปัจจุบันเสมอ

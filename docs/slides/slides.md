## สไลด์ 2 — ปัญหาที่พบ
1. นักศึกษาเดินทางเข้า–ออกมหาวิทยาลัย/หอพักทุกวัน ถ้าไปคนเดียวค่าเดินทางสูง
2. หาคนร่วมทางยาก ต้องนัดกันเองผ่าน LINE/Facebook ไม่มีระบบช่วยจับคู่
3. ไม่มีข้อมูลพิกัดและเส้นทาง ทำให้นัดรับ–ส่งคลาดเคลื่อน เสียเวลา
4. คนขับไม่มีช่องทางรับงานอย่างเป็นระบบ มองไม่เห็นงานที่รออยู่
5. รถวิ่งไม่เต็มคัน → ต้นทุนต่อคนสูง จราจรและมลพิษเพิ่มขึ้น

## สไลด์ 3 — ผู้ใช้ระบบ
**👤 ผู้โดยสาร (Passenger)**
- นักศึกษา ม.พะเยา ที่ต้องการเดินทาง
- อยากแชร์ค่าคันรถให้ถูกลง
- หาคนร่วมทางเส้นทางเดียวกัน
- ปักหมุดจุดรับ–ส่งบนแผนที่

**🚗 คนขับ (Driver)**
- นักศึกษาที่มีรถและว่างรับงาน
- แชร์ค่าเชื้อเพลิง / มีรายได้เสริม
- ดูงานว่างและกดรับงาน
- ส่งตำแหน่ง GPS แบบ Realtime

**🛠️ ผู้ดูแลระบบ (Admin)**
- จัดการฐานข้อมูลและความปลอดภัย
- ดูแลโครงสร้างตาราง (schema)
- Trigger / Function / Procedure

## สไลด์ 4 — การทำงานของระบบ
1. สมัคร / เข้าสู่ระบบ
2. ประกาศเส้นทาง + ปักหมุด
3. จับคู่กลุ่มอัตโนมัติ
4. ยืนยันสมาชิก
5. ส่งงานให้คนขับ
6. คนขับรับงาน
7. ติดตาม Realtime
8. เสร็จสิ้น + ประวัติ

## สไลด์ 5 — ฟีเจอร์: ผู้โดยสาร
1. สมัคร/เข้าสู่ระบบด้วย Supabase Auth แยกบทบาทผู้ใช้
2. ประกาศความต้องการเดินทาง: ต้นทาง–ปลายทาง + รายละเอียด + ปักหมุด GPS
3. กำหนดจำนวนผู้โดยสารเป้าหมายของกลุ่ม
4. จับคู่กลุ่มอัตโนมัติ (find_candidate_groups) รวมคนที่ไปทางเดียวกัน
5. จัดการกลุ่มเดินทาง: ดูสมาชิก / ยืนยัน / ยกเลิก
6. แผนที่ + เส้นทางจริง (OSRM) พร้อมระยะทางและเวลา
7. ติดตามสถานะแบบ Realtime และดูประวัติการเดินทาง

## สไลด์ 6 — ฟีเจอร์: คนขับ
1. Driver Dashboard แสดงงานที่รอรับ (jobs)
2. ดูรายละเอียดงานและเส้นทางบนแผนที่ พร้อมจุดรับ–ส่ง
3. กดรับงาน → สถานะเปลี่ยนเป็น accepted
4. ส่งตำแหน่ง GPS แบบ Realtime (driver_locations)
5. ดูประวัติงานที่เคยรับ

## สไลด์ 7 — เทคโนโลยีและฐานข้อมูล
**🌐 Frontend** — HTML / CSS / JavaScript, Leaflet (แผนที่), Responsive ใช้บนมือถือ
**⚙️ Backend** — Node.js + Express, REST API, ตรวจสอบสิทธิ์ด้วย Supabase
**🗄️ Database** — Supabase (PostgreSQL), 6 ตาราง + ride_group_events, Auth + Realtime

Trigger 3 · SQL Function 4 · Stored Procedure 3 · deploy แล้วบน Vercel
